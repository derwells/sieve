# SearXNG as the `jev_search` backend, 2026-09-25

A bounded live trial of a private, loopback-only SearXNG instance
(`ghcr.io/searxng/searxng:2026.9.25-12f8b6515`, started with
`bin/sieve-searxng start`) as a replacement for the Brave Search API. Script:
[`searxng_trial.py`](searxng_trial.py); raw output is written to `evals/raw/`
(gitignored). No Brave API calls were made. SearXNG's own `brave` engine
scrapes the public brave.com page, which uses no API credit.

Four public queries, one per shape:

| label | query |
|---|---|
| exact_docs | `python asyncio TaskGroup documentation` |
| broad_comparison | `PostgreSQL vs MySQL vs SQLite for a small web app` |
| recent | `latest Rust stable release 2026` |
| niche | `tree-sitter query predicates #match? #eq? syntax` |

"Usable snippet" means 40 or more characters of engine-supplied text.

## Run 1: the release's default engines, pages 1 to 3

Cumulative unique URLs after each page:

| query | p1 | p2 | p3 | usable snippets | page latency |
|---|---|---|---|---|---|
| exact_docs | 35 | 73 | 107 | 106 of 107 | 0.58–1.89 s |
| broad_comparison | 20 | 39 | 56 | 56 of 56 | 0.42–0.53 s |
| recent | 20 | 38 | 58 | 58 of 58 | 0.33–0.56 s |
| niche | 20 | 40 | 59 | 59 of 59 | 0.27–0.48 s |

`duckduckgo` returned a CAPTCHA on every request. The `brave` engine was
suspended for "too many requests" after the first query, and `wikidata` timed
out. From the second query on, every result came from `google cse` alone.

`jev_search(depth=50)` asked each of 3 variants for an even share (17 hits).
Variants overlap heavily, so the pool after dedupe was only 26–37. That led to
the change below: a paging backend asks the original query for the whole pool
and the other variants for their share.

## Run 2: `google` and `yahoo` enabled, pages 1 and 2

Only `google` and `yahoo` contributed results. Both `bing` and `qwant` were
disabled again in the shipped settings.

## Verdict

The trial passed for depth and snippets. Every query reached a 50-candidate
pool within 7 SearXNG requests and 6 s, and snippets were real and nonempty. The
risk is engine health. Upstream engines rate-limit and CAPTCHA automated
traffic, and in this trial usable results came from one or two engines at a
time. A burst of deep searches can suspend the engines that remain. SearXNG
reports those failures in `unresponsive_engines`, and sieve returns them in each
call's `usage`. With no engines left, the backend raises an error instead of
returning an empty pool. The one-hour retrieval cache avoids repeated calls to
upstream engines for the same query. The page cap (3, at most 5) and deadline
(30 s) bound each query.
